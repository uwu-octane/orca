# 关键词分类与分析工作流提案

状态：待讨论。2026-10-23。本轮只交付方案与交互原型，不接入生产分类、不执行模型调用、不变更用户数据。

后续范围变更：用户已弃用本文末尾的独立工作台原型，要求先在现有 Google 搜索结果中实现研究卡片。当前实现使用项目 Card / Tabs / Badge / FormDialog，支持字段生成、改名、新增和删除；详见 [Google provider 的卡片边界](google-keyword-provider.md#keyword-dimension-card)。以下研究集、分类与可视化仍是后续提案，不代表全部已实现。

## 产品目标

把关键词研究产生的列表变为可复查、可比较、能安排后续工作的研究资产：先看哪些词表达了什么，再判断哪些需求值得研究、哪些页面需要更新，最后把明确选中的目标加入现有收藏、排名追踪和报告。

研究入口保留 DataForSEO / Google Ads 两个 provider tab。分析工作区属于项目内的一个研究集，不属于某次 HTTP 分页结果。第一阶段从 Google Ads 结果创建研究集；共同的分析模型随后可接入 DataForSEO，但指标来源保持独立。

## 从参考讨论和实验中保留什么

1. **后续的属性组合方案优先于早期固定四层树。** 分类目录帮助组织定义；用户通过属性交集形成研究分组。点击顺序、名称、代表词不改变组的身份。无需提前生成全部属性组合。
2. **一词多归属。** 主题、任务、受众、使用场景、价格条件、实体指称可以重叠。分面归属不等于“这些词应由同一页面承接”。
3. **模型结果直接进入分析，不等待逐词审核。** 原始概率保留；归属规则版本决定当前分类。操作人员维护字段方案、按需抽样和选择分组/页面行动，不承担清空全量审核队列的工作。少量人工纠正可单独保留，但不是主流程前置条件。
4. **分类对象独立于代表词。** 代表词是人工可选的展示字段，不是分类主键，也不获得组内其他词的属性。
5. **字段生成、字段归属与具体值提取分开。** 生成模型从单行业语料提出两层字段名称；Jev 判断关键词是否表达选定字段。判断“组织规模/品牌”不等于提取 `small_business` 或 `HubSpot`，具体值提取不属于本轮字段生成或第一阶段必备流程。
6. **未归组不等于无关。** 根词可能没有特定属性；执行失败、未执行、不确定、未达候选阈值、人工否定分别保存。不能将空结果写成 0 分或“不存在该属性”。

参考实验有 4,997 词；后期字段定义为 34 个维度、99 个子维度，CRM 实际为 20 项、咖啡设备为 22 项，原目录末尾的汇总数字已过时。报告的 0.8 只是实验展示阈值，不作为产品默认接纳标准。旧意图结果是单选；不能重新标成四类多标签。参考标签未经领域专家复核，实验质量和费用不作为生产承诺。

## 分类与 decision 的职责

### 字段生成契约（按本轮确认修订）

操作人员主要修改的是行业字段结构。这里的“分类定义”指维度与子维度的命名和组织，不要求生成模型输出每个字段的定义段落。

1. 每次基于当前搜索结果的关键词集合独立生成，行业与主题从关键词中识别，不要求用户另填行业，也不套用跨行业的统一字段模板。
2. 输出较宽的“维度 → 少量子维度”两层结构。维度及数量由数据决定；不预设必选清单、层数扩展或数量配额。
3. 品牌名、型号、人群、规格等具体值不是独立字段，不按每个品牌、型号或人群分别建子维度。
4. 合并重叠、同义或过细字段，名称简短清楚，不为了凑数量扩展。
5. **生成结果只含字段名称。** 不含属性值、逐词判断、定义、证据、解释、报告、反例或验证过程。没有商家上下文，不生成商家适配或优先级结论。

输出可用两级列表展示；若接口采用结构化返回，仅包含 `dimensions: [{ name, children: [名称] }]`。稳定 ID、行业关联、输入快照与版本由应用保存，不要求模型输出。字段名称内不得夹带定义或具体值枚举。

用户随后提供的[五行业字段示例](keyword-field-examples.md)作为本轮原型的独立草案，保留原名称，不做统一模板。这些示例允许“云端”“缓震”“幼犬”等宽类别成为子维度；具体品牌、型号或数值规格不据此展开成字段。示例用于对齐输出粒度，不能推导出所有新行业的固定清单，也不代表已完成逐词分类。

生成是启发式建议，不是标准答案。用户可以重命名、增加、删除、移动子维度和合并字段；保存为方案草案后，明确选择用于哪次分类。重新生成产生独立草案，不覆盖用户编辑和已有分析。

**生成与判定使用不同任务边界。** 当前 DecisionService 是 Noul / Choice / Score 判定接口，不能直接承担开放式字段发现；字段生成需要具备文本/结构化生成能力的入口，后续确定具体模型。现有 Jev / Gateway / 本地 decision 配置继续用于批量归属判断，不承诺该入口能生成任意字段名称。

生成可读取同一行业的关键词集合；随后逐词判定只读取目标词和所用字段路径。先前“其他关键词不进入分类请求”的限制针对归属判定，不限制字段发现。生成与分类都需要固定输入范围，不能只见一页结果却声称覆盖全部行业。超出上下文的取样、拆批与合并方式另行讨论，不静默截断。

以下层次是后续分析任务的能力划分，**不是每个行业必须生成的字段清单**。意图分析也不强行塞入生成出的行业结构。

| 层次     | 输出                                           | 使用的判断                                   | 边界                                                                       |
| -------- | ---------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------- |
| 研究范围 | 核心、相邻、无关、含义不清的候选与分布         | Choice                                       | 使用已确认的业务范围；高搜索量不会改变语义相关性；无关词仍保留             |
| 搜索意图 | 知识了解、选购研究、行动获取、指定访问，可多选 | 四个独立 Noul                                | 提及品牌不必然是导航；价格词不必然是交易；不强制最大值胜出                 |
| 行业属性 | 单行业生成并由用户编辑的维度与子维度           | 独立 Noul；只有明确互斥的封闭集合才用 Choice | 有品牌不推断功能，有 CRM 不默认属于销售；具体值提取另行设计                |
| 业务适配 | 有明确标准的适配等级、候选页面匹配             | 有序 Score / 独立 Noul                       | 必须提供产品能力、服务范围或页面证据；不让模型计算 ROI、搜索量或优先级总分 |
| 页面承接 | 一个需求组的候选 URL 与需补充证据              | 对候选 URL 的语义匹配                        | 不替代 SERP 重合、页面内容和 GSC query/page 证据；缺证据时保留待验证       |
| 研究动作 | 验证 SERP、优化页面、新建页面、暂缓、追踪      | 可检查的业务条件 + 用户选择                  | 模型不直接发布页面、删词、花费预算或修改排名追踪配置                       |

小型目录先完整判断所选维度，建立召回基线。目录扩大后再单独评估候选检索；embedding 不是第一阶段前置条件。Choice 排名不得剪掉多标签结果而不说明召回变化。父维度按子维度成员并集去重，不能把独立概率相加或相乘当联合概率。

归属判定输入只包含目标关键词、语言、行业、选定字段的完整两层路径及版本化判定指令。字段生成不附送定义或正反例；若后续发现字段名歧义影响判定，另行讨论处理方式，不暗中扩写语义。搜索量、CPC、广告竞争、旧模型结果与其他关键词不进入纯属性判定。页面匹配是另一个任务，可带目标页面证据。每个问题有稳定标识，不能依赖同一请求中另一问题的回答。

例如 `best free crm for small law firms`：在相应字段存在时可判断它表达了“推荐、费用约束、组织规模、行业场景”。这些是职责边界示例，不是本轮模型调用结果。“费用约束 × 组织规模”可形成研究组，但不能把该组冒称为已抽取的“免费 × 中小企业”。应做什么页面，仍需看整组需求、SERP 和已有页面。

## 工作流及用户操作

### 1. 建立研究集

从当前结果勾选关键词，或选择已持久化的同一市场范围，创建命名研究集。明确显示选中多少词、当前只采集了哪些分页、指标日期和来源。不会把当前 150 条当作全部市场，也不会自动继续抓取后续页。

研究集固定成员与一次指标快照。刷新指标、加入新词和移除成员都是明确操作；历史分析可重新打开。Google 现有 SQL 保存的是最新指标，不能直接把它当不可变研究快照。

### 2. 按行业生成并编辑字段

直接使用当前搜索结果的关键词生成仅含两层名称的字段草案，不增加行业输入；后续研究集版本沿用此输入方式。编辑器围绕维度/子维度展开，提供重命名、增删、移动和合并；不展示逐词审核进度，不放入自动生成的定义、反例、报告或商家优先级。

保存方案版本后可用少量实际关键词试跑，也可明确发起批量分类。小样本用于观察字段是否好用，不要求人工审完全部样本才能继续。项目介绍、关键页面和商家目标只在后续需要商家适配/页面分析时明确引入。

### 3. 批量分类与质量观察

开始前固定研究集版本、分类方案、项目语境摘要和模型配置版本。任务展示总词数、完成、运行中、待处理、失败、已取消；每个词记录实际完成的问题。

完成的分类直接进入分布、交叉分析与明细，不设“待审核 / 已审核”主状态，也不让第二个模型审遍所有结果。展示已完成、未完成、失败、未归组的数量与分布；低确定性只作为质量观察入口，不生成必须清空的人工队列。

操作人员按需查看代表词或抽样，主要通过调整字段名称、合并冗余字段和明确范围改善下一次分类。查看原始分数、单词纠正属于可选细节。修改字段生成新方案版本，不给历史结果换名后冒充新模型判断；新方案在明确执行前没有分类结果。

取消停止派发新工作，已发请求完成后保存；失败项可由用户显式重新提交。任何自动重试、模型替换、输入截断、语义缓存或其他 fallback 均须另行征得用户同意，不在此提案中默认采用。

### 4. 按属性寻找机会

在完整研究集内用字段条件、关键词包含/排除、执行状态和指标范围筛选。不同字段条件默认“同时满足”；同一父维度下的子维度也可重叠，不能视作互斥值。具体值筛选在值提取能力另行实现后再增加。

保存分组时保存明确条件与分析版本。组合 `(免费, 中小企业)` 与 `(中小企业, 免费)` 为同组。浏览时的临时全文搜索不悄悄改写已保存分组。

### 5. 从分组进入页面与行动

选择分组后查看关键词、已有页面、搜索表现和验证记录。语义分组先是研究视图，只有进一步检查页面需求与 SERP 后才形成页面级主题组。

用户创建行动项：验证 SERP、优化现有 URL、新建页面草案或暂缓。记录目标市场、成员快照、主要词、页面/页面类型、理由与证据缺项；新建页面只是规划记录，不代表已发布。

确认目标词后可加入收藏或排名追踪。报告保存分析快照与行动摘要。后续用相同窗口查看 GSC 展现/点击/排名变化与 GA4 自然搜索落地页指标；时间前后变化不直接归因为本次分类或内容改动。

## 统计契约

- 关键词计数按当前完整研究集和条件去重，分页只改变渲染；交集统计不按可见页计算。
- 多标签组之间有重叠，分组数量/搜索量不相加作为总量；比较时单列共同成员。
- Google close variants 不展开成重复需求。指标按来源指标桶去重；无法可靠识别重叠时，汇总应标成估计或不可聚合，不伪装为独立总需求。
- Google 与 DataForSEO 的指标不能择优覆盖或直接相加。不同语言、地域集合、网络、币种和时间范围必须显式区分。多地域总量不能拆成各国估计。
- 0 与缺失分开。未执行/失败不计作“无属性”；低分不计作人工否定；属性集合为空不计作业务无关。
- 平均 CPC 使用平均 CPC 字段，不能用页首出价替代。原型样本没有平均 CPC，因此不展示伪造的 CPC。
- GSC 与 GA4 只在可解释的市场、日期与 URL 范围内关联；GA4 页面级转化不分摊成逐词转化。GSC 没有匹配 query 不表示其搜索量或流量为 0。
- 分组统计、代表词、表格、图表与导出使用同一快照、规则版本和筛选上下文。

Google result schema 中预留的 `typesafe/jev` 分类字段不足以表示现有多 provider 和多任务结果。正式实现时分类应独立为版本化关系，而非覆盖 `intent: unknown` 或嵌入 metrics JSON。供应商提供的 intent 与本项目的多标签意图分别展示。

## 建议的数据与执行边界

以下是逻辑对象，不是本轮迁移清单。正式建表维持 SQLite / Postgres 一致，并按项目/组织授权。

- **研究集、版本、成员与来源指标引用**：稳定 keyword identity 与 provider 观测分开；成员引用冻结指标，刷新产生新版本。原始大响应可放对象存储，关系、筛选字段与聚合指标仍在 SQL。
- **行业、字段草案、维度、子维度与方案版本**：一个方案属于一个行业，结构恰好两层；稳定 ID 与名字分开，记录生成输入及用户编辑。具体值不作为字段节点，删除采用归档以保留历史解释。
- **运行与运行项**：冻结输入、模型配置 revision、实际返回模型、问题数、耗时与错误状态；一个词分多请求时保留完整性。通用 API 当前上限为 32 个问题、64,000 序列化字符，需按契约确定性分片，不截断。
- **原始判定与问题选项概率**：逐问题存储 Noul / Choice / Score；多值概率用子表。大请求与原始响应可用受权限保护的对象存储引用；禁止记录密钥或请求头。
- **归属规则版本、成员关系、可选人工纠正**：自动分类可直接使用，无必须完成的审核状态；少量人为覆盖另存且可追溯，重新计算不悄悄撤销人工决定。
- **保存分组、条件、代表词及分析视图**：条件正规化、与点击顺序无关；明确固定快照与动态视图的区别。
- **页面映射、验证证据与行动项**：引用组版本/词、目标 URL、操作状态及后续追踪配置；不将多人协作结果只存 localStorage。

统一调用路径继续采用 server function → service → repository。后台执行承接现有任务架构，但决策请求的错误、超时和“结果未知”需单独保存；不因工作流平台默认重试而重复付费。非幂等远端调用与恢复语义在实施时单独设计。

精确复用键包括项目/授权作用域、关键词与语言、完整输入、分类/Prompt/业务语境版本、模型/endpoint/config revision。显示结果原计算时间；更换模型或定义不续接旧结果。不存在精确命中就明确需要新调用，不用近似结果代替。费用按实际 HTTP 调用记录，不能按每个问题重复计费；现有通用 API 尚未返回 Gateway 的成本元数据，任务层费用需要先补齐，拿不到时显示未知。

## 分阶段交付

**阶段一：字段驱动的分类分析。** Google 研究集快照、单行业字段生成与两层编辑器、可选小样本试跑、显式批量任务、完整集合筛选/排序、分布与交叉矩阵、保存分组和导出。先跑通“行业关键词 → 生成字段 → 用户调整 → 批量分类 → 分组分析”，不把人工逐词审核放入关键路径。

**阶段二：页面与行动。** 接入项目关键页面/审计/GSC，增加页面映射与 SERP 验证；行动清单对接收藏、排名追踪、报告；趋势与页面表现比较。所有付费或外部动作均显式触发。

**阶段三：规模与质量。** 人工标注开发/留出集、按维度/语言/模型评估精确率与召回率及校准；在保留召回证据后选择候选检索；增量重算、策略版本差异和代表词候选比较。自动建组/合并/拆分只作为建议，不自动应用。

优先讨论：字段生成使用的模型与单行业语料范围、大规模语料如何完整覆盖、字段名如何转成独立判定问题，以及第一批页面行动。阈值、综合排序权重和模型替换策略均未在此拍板。

## 本轮交互原型与证据来源

原型读取 `keywords-demo/data/clean/keywords.jsonl` 中 CRM 的 1,000 条历史记录，以及 `results/fields-full-v2` 中相同词的 20 个属性概率。只复制白名单业务字段，不读取密钥、不复用 demo UI。阈值 0.8 用于回放该实验候选，不是生产推荐；没有导入旧单选 intent，也不补造 GSC、GA4 或页面数据。

原型支持维度交叉下钻、关键词过滤/排序/分页、查看原始分数、保存分组及添加行动项。修订后去除逐词审核主流程，增加独立的两层字段草案编辑器：切换行业、改名、增删、移动、合并与保存。五个行业分别保留编辑状态，草案初始内容来自用户本轮提供的表格，不是本轮新执行的字段生成结果。编辑草案不改变历史 CRM 分类的标签、分数或统计；其他行业在此原型中只有字段草案，没有绑定可分析的关键词结果。

操作仅作用于会话演示状态，不写 Orca、不发起模型/SEO API 调用；“生成字段”在本轮原型中不可执行，等待后续接入生成服务。视觉由用户手动验收。用户提供的 `/Users/taoting/Downloads/flash-dimension-task/agent-formatted.md` 在当前机器不可访问，尚未读取该文件；本轮参考的是用户直接给出的五条规则与随后粘贴的五行业表格。
